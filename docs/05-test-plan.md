# 测试计划草案

## 当前已确认原则

- 先做 native 可测逻辑，再做上板集成验证。
- 测试计划需要覆盖安全关阀、流量精度、断网本地运行、Web 操作不影响控水等核心风险。
- 测试范围随实现范围收敛，不为不做的功能编写测试。

## Native 测试草案

- 四键输入：短按、长按、消抖、`CANCEL` 按下即停、运行中 `PLUS`/`MINUS` 无效。
- 状态机：待机、确认、运行、暂停、错误、恢复待机。
- 安全兜底：最大时间、最大出水量、超预设百分比、无流量、异常流量。
- 流量计算：脉冲计数、过滤、稳态校准系数和启动补偿水量。
- 长期运行：`millis()` / `micros()` 回绕后的超时、流量、电磁阀、显示和蜂鸣器行为。
- 本次目标调整：只在确认页按 Web 配置步进调整，容量默认 0.10L、时间默认 10s，暂停页不允许调整，且不修改预设配置。
- 结果显示：完成、停止和异常后按配置时间显示本次结果。
- 电磁阀：全压吸合、PWM 保持、关阀幂等。
- 配置：默认值、钳位、版本迁移、未来版本只读保护。
- 日志：追加、分页、容量滚动，并保存目标值、原始脉冲数、过滤脉冲数和当时流量系数。
- 统计：今日、本周、本月、总累计更新。
- 滤芯：最多 6 个滤芯，出水完成后累计流量，重置后重新计算天数和流量。
- Web 边界：路由表和页面中不存在启动出水、暂停出水、继续出水、停止出水入口。
- Web API：配置、预设、日志、统计、滤芯、校准接口返回小 JSON；最新记录校准和配置修改只接受 POST。

## 上板测试草案

- GPIO：四个按键、电磁阀、流量计、蜂鸣器、I2C LCD1602。
- 网络：WiFi 配网、mDNS hostname、Web Basic Auth、OTA 入口。
- 本地操作：选择 7.5L 预设，调整到 5L/9L，运行中暂停、继续和停止。
- 断网：WiFi 断开时本地启动、暂停、停止正常。
- 异常：拔掉流量计、关闭水源、模拟超时。
- 休眠：LCD 熄屏和按键唤醒。

## 验收标准

- `CANCEL` 软件停止响应不超过 50ms。
- 自动关阀动作不超过 100ms。
- 校准后定量误差不超过 ±3%。
- 本地结果页 `OK` 按住超过 5 秒进入校准，不等待松开；1 秒普通长按不得误进入。
- 基于记录校准使用 `pulseCount / actualMl`，对无脉冲、异常结果或偏差过大的记录拒绝保存。
- 本地暂停、继续、停止和本次目标调整必须能脱离 Web 完成。
- Web 端不得存在任何出水控制入口或 API。
- 断网不影响本地出水。
- Web 记录分页查询不影响控水 tick。
- Web API 路径不得出现 `/water/`、`/start`、`/stop` 这类远程出水控制语义。
- 重启后默认不继续未完成出水任务。
- 出水过程中所有异常优先关阀。
- 本地菜单不得修改预设值。
- 日志容量以 LittleFS 空间和性能验证后的合理值为准，目标尽量接近 20000 条。
- 滤芯查看支持最多 6 个滤芯，显示已用天数和已用流量。

## 已确认测试策略

- 长期运行测试做 72 小时连续运行。
- Native 测试使用 PlatformIO native 环境，业务核心保持纯 C++ 可测，硬件访问通过桩替代。
