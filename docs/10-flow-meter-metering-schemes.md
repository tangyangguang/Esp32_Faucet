# 流量计计量方案设计

本文定义“流量计计量方案”模型。本文只描述方案设计，不包含代码实施步骤。

普通校准流程已实现为“校准会话”。校准会话生成合格结果后，用户在校准页“确认应用”会创建并设为当前方案；这是面向普通用户的校准完成动作。从长期样本库生成方案时，生成结果先保存为新方案，再由用户显式设为当前。

## 目标

流量计计量方案用于保存水流量计把脉冲换算成水量时使用的一整套参数。它和具体流量计、水路、水压、滤芯状态、安装环境有关。

系统需要支持多套方案，目的包括：

- 实验时保存多套参数，便于切换对比。
- 长时间使用某套方案后发现效果不好，可以快速切回以前验证过的方案。
- 不同水压、水路或流量计条件下，可以使用不同方案。
- 生成结果后，先查看结果和样本依据，再决定是否保存和设为当前。

## 命名

页面和文档统一使用以下名称：

- 流量计计量方案：一套可保存、可设为当前的计量参数。
- 当前计量方案：设备正在用于出水估算的方案。
- 系统内置默认方案：首次启动或默认方案缺失时由系统创建的兜底计量方案。
- 计量方案生成结果：根据样本生成、尚未保存为正式方案的结果。
- 新建计量方案：手工输入名称和 5 个计量参数创建的方案。
- 修改计量方案：仅允许修改未使用、未删除方案的名称和 5 个计量参数。
- 当前方案：唯一正在使用的方案。
- 逻辑删除方案：已删除但槽位尚未被新方案复用的方案。

不再使用固定位置编号作为用户概念。

## 计量参数

每套方案保存 5 个计量参数，按用途分为两组。

容量估算计量参数用于根据有效脉冲估算实际出水容量：

- 启动脉冲数 `Ns`
- 启动水量 `Vs`
- 稳态 P/L `Ps`

容量估算公式保持不变：

```text
P = 0:
  V = 0

0 < P <= Ns:
  V = round(P * Vs / Ns)

P > Ns:
  V = Vs + round((P - Ns) * 1000 / Ps)
```

`Ns = 0` 且 `Vs = 0` 时，启动段等价于没有，全部有效脉冲按稳态 P/L 计算。

时间估算计量参数用于根据目标容量估算预计出水时间和预计稳态流速：

- 启动时长 `Ts`，单位 ms。
- 预计稳态流速 `Fs`，单位 ml/min。

时间估算参数只用于预设、确认页等位置的预计展示，不参与实际出水容量、滤芯累计或统计累计。任何实际容量都必须由容量估算计量参数按有效脉冲计算；异常出水或 0 脉冲不能用时间估算补容量。

目标容量预计时间：

```text
Ts = 0 或 Vs = 0:
  T = V * 60000 / Fs

V <= Vs:
  T = V * Ts / Vs

V > Vs:
  T = Ts + (V - Vs) * 60000 / Fs
```

给定时间预计容量：

```text
Ts = 0 或 Vs = 0:
  V = T * Fs / 60000

T <= Ts:
  V = T * Vs / Ts

T > Ts:
  V = Vs + (T - Ts) * Fs / 60000
```

## 方案数量与状态

业务上不设置固定的方案数量上限。页面不能把某个固定数量作为用户规则，也不能显示固定空位。

方案列表按动态数据展示。默认只显示未逻辑删除方案。

底层实现可以有工程容量边界，用于保护 Flash、RAM 和页面响应时间。达到工程容量时，用户需要先逻辑删除一个非当前方案，之后新方案才能复用已删除槽位。

每套方案有两个关键状态：

- `deleted`：是否逻辑删除。
- `usedEver`：是否已经被成功出水记录引用过。

当前计量方案必须始终是未删除且参数有效的方案。

系统必须始终至少有一套当前计量方案。当前计量方案不能删除。

## 系统内置默认方案

首次启动或方案文件缺失时，系统创建一套内置默认方案：

- 名称：`YF-S201 默认计量方案`。
- 启动脉冲数：`8P`。
- 启动水量：`130ml`。
- 稳态 P/L：`248P/L`。
- 启动时长：`5000ms`。
- 预计稳态流速：`1950ml/min`。
- 来源：系统内置默认方案。

这套方案用于保证设备烧录后立刻具备可用计量参数。它和其他方案一样遵循使用状态和逻辑删除规则；系统任何时刻都不能没有当前方案。

## 方案数据

每套方案保存以下结构化数据：

- `id`：稳定 ID，创建后不复用。
- `recordUsed`：底层槽位是否占用，仅作为存储层槽位状态，不作为页面概念。
- `deleted`：是否已逻辑删除。逻辑删除方案不出现在普通方案列表中，不能设为当前方案，槽位满时可被新方案复用。
- `name`：用户可编辑名称。
- `startupPulseCount`：启动脉冲数。
- `startupVolumeMl`：启动水量，单位 ml。
- `stablePulsePerLiter`：稳态 P/L。
- `startupDurationMs`：启动时长，单位 ms，仅用于预计展示。
- `stableFlowMlPerMin`：预计稳态流速，单位 ml/min，仅用于预计展示。
- `sourceType`：`default`、`calibration_session`、`long_term_samples`、`manual`。
- `revision`：方案修订号，创建为 1，修改 5 个计量参数时递增。
- `createdAt`：创建时间。
- `updatedAt`：最近修改时间。
- `usedEver`：是否已经被至少一条出水记录使用过。

如果方案来自样本生成，额外保存最小生成摘要：

- `sampleCount`：生成时使用的有效样本数量。普通校准为 2-3 条，长期样本生成为 2-5 条。
- `minActualMl`：生成样本中的最小实测水量。
- `maxActualMl`：生成样本中的最大实测水量。
- `maxErrorMl`：生成拟合后的最大绝对误差。
- `maxErrorTenthPercent`：生成拟合后的最大相对误差，使用整数十分之一百分比保存。

计量方案长期记录不保存参与样本 traceId 数组、启动阶段最小/最大/中位/平均统计、长篇创建说明、长篇最近修改说明、流量计标识、水路标签、环境标签、用户备注、精确累计使用次数、最近使用时间或使用状态 dirty 标记。这些信息不参与运行计量，且会显著增加 Flash 常驻数据、存储复杂度和页面负担。

手工新建方案没有样本依据，`sourceType` 为 `manual`，样本统计字段为 0。

## 计量方案生成结果

计量方案生成结果来自已保存样本。生成方案不会保存正式方案，也不会影响当前计量。

生成结果只是临时候选：可以保存在 RAM 中，也可以由页面/API 基于当前样本即时重新计算；不作为独立长期 Flash 数据。设备重启、用户离开页面或放弃生成结果后，可以丢弃候选结果，用户需要时重新生成即可。

生成结果显示：

- 5 个计量参数，并按容量估算计量参数和时间估算计量参数分组显示。
- 样本数量。
- 实测水量范围。
- 最大误差。
- 最大相对误差。
- 生成时间。

启动阶段时长可作为本次生成结果的临时辅助信息显示，但不写入正式计量方案记录。

专业计量方案页的生成结果只提供两个操作：

- 保存为新方案。
- 放弃生成结果。

生成结果不能直接设为当前方案，不能覆盖已有方案，也不能覆盖当前方案。

保存生成结果后，系统创建一套新的流量计计量方案。保存动作不切换当前方案。用户需要显式点击“设为当前”后，设备才切换计量参数。

普通校准会话中的“确认应用”是例外流程：用户已经处于校准完成上下文中，确认后系统创建并设为当前方案，同时保留旧方案和生成依据摘要。

## 操作规则

### 生成结果

系统只使用已入库、容量已校准、未截断、未发生暂停后恢复出水且稳态识别成功的样本生成方案。

RAM 临时明细只用于查看和校准入口，不直接参与生成。用户在校准页样本列表中校准 RAM 明细容量时，系统必须先保存到设备样本库；入库失败时本次校准失败。

生成结果必须有明确质量门槛：

- 有效样本数量不少于 2 条。
- 样本容量覆盖小容量和大容量，最大实测水量和最小实测水量差值不少于 500ml。
- 生成结果保存样本数量、实测容量范围、最大绝对误差和最大相对误差。
- 最大绝对误差不超过 100ml，最大相对误差不超过 5%。超过阈值时，只显示诊断结果，不生成可保存结果。
- 若同一容量附近有多次样本，可在临时诊断中显示重复性差异；不写入长期方案记录。
- 稳态识别失败、暂停恢复、明细截断或未确认实际容量的样本不能参与生成。

质量门槛不满足时，页面只能显示诊断原因，不能生成可保存的生成结果。

### 保存为新方案

保存生成结果时只能创建新方案，不允许选择已有方案覆盖。

如果底层方案槽位已满，保存失败并提示先逻辑删除一个非当前方案。只有已逻辑删除槽位会被新方案复用。

保存成功后，生成结果可以清空，避免重复保存同一结果。

### 新建计量方案

用户可以手工新建方案，填写：

- 方案名称。
- 启动脉冲数。
- 启动水量。
- 稳态 P/L。
- 启动时长。
- 预计稳态流速。

手工新建方案不需要样本依据，不自动设为当前方案。

### 修改计量方案

只有 `usedEver = false` 且未逻辑删除的方案允许进入修改页。修改页允许编辑：

- 方案名称。
- 启动脉冲数。
- 启动水量。
- 稳态 P/L。
- 启动时长。
- 预计稳态流速。

修改不改变生成摘要。系统只更新 `updatedAt`，计量参数变化时递增 `revision`。

如果修改的是当前方案，保存后会立即影响后续容量估算和预计展示，页面必须明确提示这一点。

修订号规则：

- 新建方案的 `revision` 为 1。
- `revision` 只作为方案记录自身的辅助字段，不作为出水记录追溯所需的主要依据。
- 从未被出水记录使用过的方案，可以直接修改名称和 5 个计量参数。
- 已经被出水记录使用过的方案不允许继续修改；如果需要不同参数或名称，必须创建新的方案 ID。
- 后续历史记录展示以出水记录保存的方案 ID 反查对应方案，不能用当前方案的参数反推历史。

生成摘要始终代表该方案创建时的样本快照。

### 当前方案

设为当前是单独操作。只有设为当前后，方案才成为当前计量方案。

只有未逻辑删除、参数有效的方案可以设为当前。

设为当前方案时更新：

- `activeSchemeId`
- 运行时 `FlowMeter` 使用的计量参数

设为当前不修改方案的生成摘要。

### 删除方案

当前方案不能删除。若用户要删除当前方案，必须先把另一套未删除方案设为当前。

删除一律是逻辑删除，不做物理删除。非当前方案都可以逻辑删除，不受 `usedEver` 限制。

槽位未满时，新方案优先使用空槽位。槽位满时，新方案只复用已逻辑删除槽位；复用槽位会覆盖旧方案记录，但新方案 ID 继续递增，不复用旧 ID。

系统必须始终保留一套当前方案，并且 `activeSchemeId` 必须指向一套未删除、参数有效的方案。

## 出水记录追溯

每条成功生成的出水记录必须保存当时使用的计量方案引用：

- `meteringSchemeId`
- 如果实现里仍保留 `meteringSchemeRevision`，它只作为辅助显示字段，不作为保存完整计量参数快照的理由。

出水记录不保存 `startupPulseCount`、`startupVolumeMl`、`stablePulsePerLiter`、`startupDurationMs`、`stableFlowMlPerMin` 等完整计量参数快照。历史追溯由方案记录承担：如果用户需要调整已使用方案，必须创建新的方案 ID。方案文件固定 50 槽，槽位满后系统只覆盖已逻辑删除槽位；被覆盖方案对应的早期历史记录显示“方案已覆盖，历史参数不可查看”。

为减少普通出水后的高频 Flash 写入，方案记录不维护精确累计使用次数和最近使用时间，只维护低频使用状态：

- 每条出水记录必须保存方案 ID。
- 方案记录使用 `usedEver` 表示是否至少被成功出水记录使用过。
- `usedEver` 只允许从 false 变为 true，不需要每次出水都更新。
- 首次成功出水后，如果该方案的 `usedEver` 仍为 false，运行时先把当前方案视为已使用，再尽力把它持久化为 true；后续成功出水不再写方案记录。
- 如果这次 `usedEver` 持久化失败，出水记录仍然保留，当前运行周期内该方案仍按已使用处理，不能继续编辑；失败不影响关阀安全。
- 页面显示“未使用过”或“已使用”，不显示精确使用次数。
- 删除判断保持简单：当前方案不能删除；非当前方案都可以逻辑删除；系统自动创建新方案且 50 槽已满时，只允许复用已逻辑删除槽位。

## 页面结构

计量方案页按任务分区：

1. 当前计量方案
   - 显示当前方案名称。
   - 显示 5 个计量参数，并区分容量估算计量参数和时间估算计量参数。
   - 明确提示时间估算计量参数只用于预计展示，不参与实际容量、滤芯累计或统计累计。
   - 显示来源、最小生成摘要和最近修改时间。

2. 计量方案生成结果
   - 显示生成结果和样本依据。
   - 提供“保存为新方案”和“放弃生成结果”。
   - 明确提示“保存不会自动设为当前”。

3. 流量计计量方案
   - 动态列表显示已有方案。
   - 当前方案有明确标记。
   - 每套方案显示名称、参数摘要、来源、最小生成摘要、使用状态和最近修改时间。
   - 未使用方案显示“修改”。
   - 非当前方案显示“设为当前”和“删除”。
   - 已使用方案不显示“修改”；需要变化时新建方案。

4. 新建计量方案
   - 提供手工新建入口。
   - 表单分组显示容量估算计量参数和时间估算计量参数。
   - 新建后不自动设为当前。

5. 样本库摘要
   - 展示长期样本库的覆盖范围和有效样本数量。
   - 显示容量校准、稳态识别、是否可参与生成。
   - 本次校准会话的出水、实测容量录入和放弃本次样本不在本页操作，统一放在 `/faucet/calibration`。

校准页只承担普通校准会话：进入/退出校准模式、录入本次实测容量、放弃本次样本、生成并确认应用。它不提供手工方案管理、长期样本库生成、方案列表或测算工具。

## 存储策略

流量计计量方案应从 `SystemConfig` 中拆出，使用独立的 `MeteringSchemeStore` 管理。

`SystemConfig` 继续保存安全阈值、显示、蜂鸣器、滤芯、预设等系统配置。流量计计量方案独立保存：

- 计量方案存储版本。
- 当前方案 ID。
- 下一个方案 ID。
- 方案数量。
- 方案记录。

生成结果候选不列入长期存储结构。保存方案时只写入被修改的方案和必要索引，不重写整个系统配置。设为当前只写当前方案 ID；修改、逻辑删除、首次 `usedEver` 标记只写对应方案记录。这样可以减少写入量，降低 Flash 磨损。

方案数量不再是固定小数组，因此方案记录适合使用独立记录式持久化。当前方案 ID、存储版本和少量索引可以放在 NVS；方案记录可以放在 LittleFS 定长记录文件或等价的记录式存储中。脉冲明细样本使用独立样本库，不放入方案配置。

普通校准会话样本和长期样本库使用独立空间：

- RAM：只保留当前/最近一次完整脉冲明细。
- 会话样本区：Flash 最多保存 3 条有效样本完整明细，新会话可覆盖上一会话。
- 长期样本库：Flash 固定 5 条完整明细，不自动覆盖。

会话样本区和长期样本库都不应作为开机硬依赖预创建大文件。首次保存有效样本或长期样本时再懒创建；空间不足时清晰提示用户，不影响普通出水、安全关阀或出水记录写入。

计量方案页从长期样本库生成方案；校准页从当前会话有效样本生成并确认应用。

## 文件格式

计量方案文件头必须包含当前存储版本和记录大小。版本、记录大小、槽位数量或校验不匹配时，系统报告格式不兼容或损坏，不自动改写文件；测试阶段通过格式化 LittleFS 或重建方案文件恢复。

## 文案原则

- 不使用固定位置编号作为用户概念。
- 不使用“覆盖当前方案”作为生成结果保存动作。
- “保存为新方案”和“设为当前”必须分开。
- 所有会影响当前计量的操作必须显式提示。
- 已使用方案不显示编辑入口；非当前方案仍可逻辑删除。
- 每套方案必须显示使用状态，不追求精确使用次数。
- 每套方案必须分组显示“容量估算计量参数”和“时间估算计量参数”。
- 页面必须明确“时间估算计量参数只用于预计展示，不参与实际容量、滤芯累计或统计累计”。
- “实时流速”“预计流速”“平均流速”必须区分显示，不混用。
- 生成样本依据只以最小摘要永久保留。
- 修改方案只更新最近修改时间，不改变生成摘要。
