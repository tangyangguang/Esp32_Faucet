# 配置持久化与迁移说明

## 配置域

- 系统业务配置：保存在 `faucet_cfg`，包含安全阈值、本地交互参数、电磁阀参数、计量参数槽、预设和滤芯基础设置。
- 运行累计状态：统计保存在 `faucet_stat`；滤芯运行状态保存在 `faucet_run`。
- 历史记录：出水记录、记录校准元数据和脉冲明细分别保存在 LittleFS 文件，不与系统配置版本耦合。
- Web/AppConfig 暴露参数：只覆盖系统业务配置中的基础参数；保存时必须先通过 `ConfigStore` 加载并迁移完整配置，再合并提交字段。
- 滤芯基础设置：名称、启用、建议更换周期、最长使用周期和寿命流量属于 `faucet_cfg`。
- 滤芯运行状态：上次更换时间、已用流量和启动 boot id 属于 `faucet_run`。

## 加载和迁移入口

`ConfigStore::loadSystemConfig()` 是唯一可信入口。其他模块不得直接写 `faucet_cfg/ver`，也不得用默认结构覆盖未暴露字段。

加载流程：

1. 读取 `faucet_cfg/ver`。
2. 如果版本缺失，继续探测可识别旧字段；只要存在旧预设、滤芯、计量或基础参数字段，就按旧结构迁移，不能直接返回默认值。
3. 已知旧版本先读取所有可识别字段，再补齐当前默认新增字段并钳位。
4. 未来版本按当前可识别字段只读加载，拒绝保存，避免降级固件覆盖新固件数据。
5. 迁移写回时先写当前字段，最后写当前版本号；迁移失败不清旧字段，也不写半成品当前版本。

## 滤芯迁移规则

- 旧 `fN_life_d` 迁移为 `fN_life_min` 和 `fN_life_max`，两者取同一旧值。
- 旧系统配置中的 `fN_start`、`fN_used` 只作为迁移来源；迁移成功后写入 `faucet_run`。
- 修改滤芯基础设置不会清空运行状态。只有用户执行滤芯重置或更换日期变更时，才更新上次更换时间和已用流量。
- 运行状态保存只写 `faucet_run`，不会覆盖名称、启用、寿命等基础设置。

## 保存路径

- AppConfig 保存回调只重新加载 `ConfigStore` 当前完整配置并热应用；它不能直接标记业务配置版本。
- Web 配置、预设、滤芯和计量参数保存必须基于 `ConfigStore::loadSystemConfig()` 返回的完整当前配置。
- 保存失败时不更新运行时 `g_config`、`FilterStore` 或 `AppController`。
- 出水、确认、暂停或结果页期间拒绝热更新配置。

## 可观测性

启动日志会输出配置加载状态、原始版本、目标版本、迁移是否写回和是否只读。`/api/faucet/status` 的 `config` 节点输出同样的非敏感诊断字段。

## 双 OTA 槽位恢复注意事项

WebOTA 后如果 `otadata` 仍指向旧 OTA 槽位，设备可能继续启动旧固件，造成“恢复后配置又丢失”的误判。串口恢复或排障时需要确认实际启动分区；必要时对两个 OTA 槽都写入目标固件，或清除 `otadata` 后再烧录，确保启动的是正在验证的新固件。
