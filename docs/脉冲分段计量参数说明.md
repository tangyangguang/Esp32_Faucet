# 脉冲分段计量参数说明

本文是“脉冲分段计量参数”的用户说明，用来统一页面概念、参数含义和校准流程。它只描述用户需要理解和操作的内容，不描述代码实施步骤。

## 设计边界

旧的“控制 P/L、启动补偿、启动等效”概念不再作为页面概念、文档概念或代码设计概念保留。

新的设计只保留“脉冲分段计量参数”这一套模型：

- 启动脉冲数
- 启动水量
- 稳态 P/L

后续实现时，旧概念对应的变量、配置字段、页面文案和算法路径都应被移除或迁移，不再作为兼容设计继续存在。

## 要解决的问题

当前设备用单一 P/L 系数估算出水量。大容量出水时，这个系数通常比较稳定；但小容量出水时，开阀初期的水流爬坡会占比较大，容易出现偏差。

新的计量模型把一次出水分成两段：

- 启动段：开阀后的前几个脉冲，水流还没有完全稳定。
- 稳态段：水流稳定后的脉冲，按稳定 P/L 计算。

这样做的目标是让小容量和大容量都能用同一套参数解释，而不是用一个全程平均 P/L 去硬套所有容量。

## 核心概念

### 脉冲分段计量参数

一套参数只用 3 个字段真正参与计量：

- 启动脉冲数：启动段包含多少个脉冲。
- 启动水量：启动段这些脉冲对应多少 ml 水。
- 稳态 P/L：进入稳定流量后，每升水对应多少个脉冲。

页面上应优先用这 3 个概念解释当前设备如何计量。

除这 3 个字段以外，生成参数时用到的样本数量、容量范围、最大误差、启动阶段最短时间、最长时间、中位数等信息，都不作为可编辑参数保存。它们只写入参数槽的创建说明，作为后续观察和追溯材料。

### 启动时长

启动时长只表示生成参数时，样本中观察到“进入稳态大概需要多久”。它不是控制边界，不参与计量公式，也不作为独立参数保存。

页面可以显示为：

```text
启动时长：典型 5s，范围 3-7s
```

如果启动时长范围很散，例如 2-15s，说明启动过程波动大，这套参数需要谨慎使用。这类信息写在参数槽的创建说明里，创建后不再随样本变化。

### 全程平均 P/L

全程平均 P/L 不能作为独立系统参数，因为它会随出水量变化。

它只能出现在有明确水量上下文的位置：

- 历史记录：本次总脉冲和本次实测水量对应的全程平均。
- 容量预设：当前启用参数下，某个目标容量预计会表现出来的等效全程平均。

页面不应单独显示一个没有上下文的“全程平均 P/L”。

## 计量逻辑

设：

```text
P  = 当前累计有效脉冲数
Ns = 启动脉冲数
Vs = 启动水量，单位 ml
Ps = 稳态 P/L
V  = 估算出水量，单位 ml
```

计量公式为：

```text
P = 0:
  V = 0

0 < P <= Ns:
  V = P × Vs / Ns

P > Ns:
  V = Vs + (P - Ns) × 1000 / Ps
```

含义是：前 `Ns` 个脉冲按启动段估算，超过 `Ns` 后按稳态 P/L 估算。

## 参数从哪里来

参数来自已保存的出水样本。一个样本要参与生成参数，需要同时满足：

- 有脉冲明细。
- 已输入或确认量杯实测水量。
- 能识别出稳定流量段。
- 已保存到设备样本库。

RAM 临时明细只用于查看和判断，不能直接参与生成。需要参与生成时，用户先把它保存到设备。

## 候选参数、参数槽和当前启用

系统最多保存 4 套参数。

- 候选参数：根据当前样本生成出来的新参数，还没有进入参数库。
- 参数槽：保存参数的位置，可以理解为 1-4 号参数档案。参数槽固定为 4 个，允许用户修改槽名称。
- 当前启用参数：设备实际用于出水计量的那一套参数。

三类操作必须分开：

- 生成候选参数：只产生候选，不影响当前出水。
- 保存到参数槽：把候选保存到某个槽位，不自动启用。
- 启用参数槽：用户明确选择某个槽位后，设备才切换到这套参数。

这样可以让用户保存多套实验参数，并在确认后再切换，避免生成新参数时误影响当前计量。

候选参数必须先保存到参数槽，不能直接启用。保存规则如下：

- 保存到非当前启用槽位：只覆盖该槽位，不自动启用。
- 保存到当前启用槽位：允许覆盖，并立即生效；页面动作必须明确写成“覆盖当前启用参数”，避免用户误以为只是保存备用参数。

参数槽保存两类说明：

- 创建说明：生成或手工创建参数时写入的固定文本。自动生成时记录样本数量、容量范围、最大误差、启动阶段最短时间、最长时间、中位数等；手工创建时记录“手工创建”和创建时的 3 个核心参数值。
- 最近修改：用户修改槽位参数时写入修改时间、修改前 3 个核心参数值、修改后 3 个核心参数值。

创建说明用于解释参数来源，创建后不再自动变化。最近修改只保留上一次修改，避免把参数槽变成复杂历史日志。

## 推荐页面结构

校准页建议按用户任务分成 4 块：

1. 当前启用参数
   - 显示正在使用哪一个参数槽。
   - 显示启动脉冲数、启动水量、稳态 P/L。
   - 显示该参数槽的创建说明和最近修改记录。

2. 候选参数
   - 显示根据当前样本生成的新参数。
   - 明确提示“生成后不会自动启用”。
   - 提供保存到某个参数槽的入口。

3. 参数库
   - 显示 4 个参数槽。
   - 每个槽可以查看、重命名、启用、编辑 3 个核心字段，或用候选覆盖。
   - 空槽可以新建。

4. 样本区
   - 显示 RAM 临时样本和已保存样本。
   - 显示容量是否已确认、稳态是否识别成功、是否可参与生成。
   - 支持保存或删除样本。

## 推荐操作流程

1. 按常规方式本地出水。
2. 在校准页确认最新记录的实际容量。
3. 查看脉冲明细，确认样本质量。
4. 把合格明细保存到设备样本库。
5. 积累多个容量的有效样本。
6. 手动生成候选参数。
7. 检查候选参数的样本数量、容量范围、误差和启动时长。
8. 把候选保存到某个参数槽。
9. 如果保存到了非当前启用槽位，再手动启用该参数槽。
10. 如果覆盖的是当前启用槽位，保存后参数立即生效。
11. 再用不同容量复测。

## 页面文案原则

- 不再使用旧概念，例如“控制 P/L”“启动补偿”“启动等效”。
- 优先使用用户能直接理解的“当前启用参数”“候选参数”“参数槽”“启动脉冲数”“启动水量”“稳态 P/L”。
- 手动编辑参数槽时，只允许编辑启动脉冲数、启动水量、稳态 P/L 这 3 个核心字段。
- 所有会改变当前计量行为的动作，都要明确显示结果，例如“启用参数槽 2”。
- 生成候选参数要明确提示“不自动启用”。
- 保存候选到非当前启用槽位要明确提示“不自动启用”。
- 保存候选到当前启用槽位要明确提示“覆盖后立即生效”。
- 全程平均 P/L 只跟具体记录或具体预设一起显示。

## 后续实现约束

后续代码实现应以新模型为唯一运行时计量模型：

- 出水计量不再使用“单一 P/L + 启动补偿”。
- 配置中不再保存“控制 P/L、启动补偿、启动等效”这些独立概念。
- 历史配置升级时，只允许把旧字段迁移成新的 3 个核心字段，迁移后不再继续保存旧字段。
- 参数槽中只有 3 个核心参数是结构化计量字段；样本统计、启动时间范围和误差等只进入创建说明文本。
- 页面、API 和测试用例都应使用新概念命名。
