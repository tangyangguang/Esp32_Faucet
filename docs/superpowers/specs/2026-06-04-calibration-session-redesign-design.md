# 校准会话重构设计

## 背景

当前 Web 校准页同时承载样本校准、样本覆盖、计量方案生成、计量方案管理、脉冲明细诊断和公式说明。页面信息密度过高，也把普通用户的校准流程和技术人员的样本/方案分析混在一起。

智能定量出水设备需要一个面向普通用户的校准流程：用户准备量杯或容器，按设备本地按键完成若干次校准出水，录入真实出水量，设备根据有效样本生成并应用新的计量方案。同时，技术人员仍需要保留样本、脉冲明细、生成依据和计量方案管理能力。

本设计将“校准”从单个页面重构为设备级“校准会话”，并将普通校准流程、长期样本库和计量方案管理分层。

## 参考原则

- 成熟校准产品通常使用引导式校准流程，重点是按预定义步骤执行、记录结果、保留可追溯依据。
- 校准过程和计量方案生效应有明确边界：记录事实、生成评估、确认应用分别处理。
- 复杂细节应按需展开。普通用户默认看到流程和结果，专业人员通过样本详情、生成依据、方案依据查看技术细节。
- 当前版本 Web 不提供远程出水控制能力。Web 可以进入校准、录入实测容量、放弃样本和确认应用，但启动、暂停、继续、停止出水只能通过设备本地按键完成。

参考资料：

- Beamex CMX / LOGiCAL calibration process: https://www.beamex.com/us/calibration-software/cmx/
- Fluke MET/CAL calibration software: https://www.fluke.com/en-us/product/fluke-software/fluke-calibration-software/node/13417
- GAGEtrak compliance and audit trail: https://gagetrak.com/standards-compliance/
- NN/g customization and progressive disclosure guidance: https://media.nngroup.com/media/reports/free/Customization_Features_Done_Correctly.pdf

## 目标

- 提供默认的引导式校准会话，让普通用户按步骤完成校准。
- 本地和 Web 共享同一个校准会话状态。
- Web 可辅助录入和确认，但不控制阀门。
- 允许用户放弃单次失败样本，保证校准流程有容错性。
- 本次校准会话样本和长期样本库分开存储。
- 计量方案应用必须经过用户确认，旧方案保留。
- 校准出水仍按普通出水计入统计和滤芯累计。
- 专业信息通过样本库、样本详情、生成依据、方案依据进入，不设置顶级“诊断”导航。

## 非目标

- 不允许 Web 启动、暂停、继续或停止出水。
- 不实现旧脉冲明细或旧样本库迁移。旧文件不读、不删、不覆盖。已有计量方案配置仍按现有模型保护，不因本次样本存储重构静默丢失。
- 不强制新机先校准。内置默认计量方案仍可正常运行，只提示“建议校准后更准确”。
- 不在首版实现压缩脉冲存储格式。
- 不在本项目内修改 Esp32Base。

## 导航

Web 主导航调整为：

```text
首页 | 记录 | 统计 | 预设 | 滤芯 | 校准 | 计量方案
```

`校准` 是引导式校准会话的默认入口。`计量方案` 管理当前设备如何把脉冲换算为水量。

不新增顶级“诊断”页。相关入口按上下文命名：

- 出水记录中叫“脉冲明细”。
- 校准样本中叫“样本详情”。
- 生成结果中叫“生成依据”。
- 计量方案中叫“方案依据”。
- 校准页高级入口叫“样本库”。

## 校准会话流程

### 正常流程

```text
开始校准
  -> 设备进入 CAL 状态
  -> 用户准备量杯或容器并打开水路
  -> 本地按 OK 开始本次校准出水
  -> 出水结束，形成普通出水记录和 RAM 脉冲明细
  -> 本地或 Web 输入实测容量，或放弃本次样本
  -> 保存有效样本到校准会话样本区
  -> 达到生成条件后生成结果
  -> 用户确认应用
  -> 创建并启用新计量方案
```

### 样本数量规则

- 最少有效样本：2 条，可快速生成。
- 推荐有效样本：3 条，推荐生成。
- 最多有效样本：5 条，参与本次生成。
- 最多会话尝试：10 次，包含有效、放弃、系统判定无效的尝试。

达到 5 条有效样本后不再安排新的校准出水。达到 10 次尝试仍不满足生成条件时，会话进入无法继续状态，并提示检查水路、量杯或流量计。

5 条有效样本的设计取舍：

- 普通校准推荐 3 条，5 条仍允许用户额外追加 2 条用于复测或扩大容量覆盖。
- 2 条可快速生成、3 条推荐生成、4-5 条高级追加的层级更清晰。
- 相比 6 条，会话样本区减少 1 个完整明细槽位，降低 Flash 占用和页面复杂度。
- 长期样本库容量已被 `2026-06-11-flash-storage-consolidation-design.md` 收敛为 5 条；专业人员需要更多历史样本时应通过导出或外部分析处理，而不是继续扩大设备端 Flash 常驻空间。

### 容量覆盖规则

系统不强制固定 500ml、1500ml、7500ml 等目标点。页面和本地只给容量差距建议：

```text
建议完成至少 2 条有效样本。
推荐 3 条：小容量、常用容量、较大容量。
最大实测容量与最小实测容量建议至少相差 1L。
```

生成质量分级：

- 容量跨度小于 500ml：不建议生成，提示容量跨度不足。
- 容量跨度 500-999ml：允许快速生成，但强提示覆盖偏窄。
- 容量跨度 1000ml 以上：推荐生成。

实际生成质量仍需结合有效样本数、稳态识别、拟合误差和相对误差。

### 放弃样本

出水结束后，用户可以放弃本次样本。常见原因：

- 量杯溢出或读数不准。
- 未接好水。
- 水路未打开或长时间无水后才恢复。
- 误操作。
- 其他。

放弃样本规则：

- 不删除普通出水记录。
- 不影响统计和滤芯累计。
- 不自动保存完整明细到长期样本库。
- 在会话中记录放弃原因。
- 不计入有效样本数。
- 系统继续安排下一次校准尝试，优先补测当前缺失或失败的容量区间。

### 系统判定无效

以下样本不参与生成：

- 暂停后恢复出水。
- 脉冲明细截断。
- 无实测容量。
- 无有效脉冲或无法分析。
- 稳态识别失败。
- 异常错误结果，除非后续明确扩展某类异常的分析价值。

其中“暂停后恢复出水”仍允许作为安全操作，但本次样本自动标记为不可参与生成。

## 会话状态机

```text
Idle
  无校准会话

Preparing
  已进入校准模式，等待用户准备容器和水路

WaitingLocalRun
  等待本地按 OK 开始本次出水

Running
  本地正在出水

AwaitingActual
  本次出水结束，等待输入实测容量或放弃

ReadyToGenerate
  已有足够有效样本，可生成

Generated
  已生成结果，等待确认应用

Applied
  已创建并启用新计量方案

Discarded
  用户放弃整个会话

Failed
  会话无法继续，例如存储不可用或尝试次数用完
```

主要转移：

```text
开始校准 -> Preparing
确认准备 -> WaitingLocalRun
本地 OK 出水 -> Running
出水结束 -> AwaitingActual
保存实测容量成功 -> WaitingLocalRun 或 ReadyToGenerate
放弃本次 -> WaitingLocalRun 或 Failed
生成结果 -> Generated
确认应用 -> Applied
退出会话 -> Discarded
```

## 本地按键

校准模式下按键语义：

- `OK`
  - 准备页：继续。
  - 等待出水：开始本次出水。
  - 输入容量：保存实测容量。
  - 生成结果：确认应用。
- `PLUS` / `MINUS`
  - 输入容量时调整实测容量。
  - 等待出水时切换容量建议标签或目标提示。
- `CANCEL` 短按
  - 输入容量时放弃本次样本，并进入二次确认。
  - 其他非出水状态返回上一层或提示退出会话。
- `CANCEL` 长按
  - 退出整个校准会话，并进入二次确认。
- 出水中
  - `CANCEL` 停止本次出水，进入实测容量录入。
  - `OK` 保持现有暂停语义。只要发生暂停后恢复，本次样本不参与生成。

## Web 边界

Web 可执行：

- 开始校准会话。
- 退出未出水中的校准会话。
- 查看当前校准状态。
- 查看有效样本数、尝试次数、容量跨度。
- 输入或修改本次实测容量。
- 放弃本次样本并选择原因。
- 生成校准结果。
- 确认应用校准结果。
- 查看样本库、样本详情、生成依据、方案依据。

Web 不可执行：

- 开始出水。
- 暂停出水。
- 继续出水。
- 停止出水。

Web 开始校准前提示：

```text
进入校准模式后，设备本地按键将切换为校准流程。
网页不会启动、暂停或停止出水；出水必须在设备旁通过本地按键操作。
请确认已准备量杯或接水容器，并已打开水路。
```

## 存储设计

### 总体分层

```text
RAM 最近明细
  临时缓存，只保留最近 1 条出水明细，重启丢失

校准会话样本区
  Flash 持久化，保存当前/最近一次校准会话最多 5 条有效样本明细
  新会话开始时覆盖旧会话数据

长期样本库
  Flash 持久化，最多 10 条样本明细
  用户明确点击“存入长期样本库”才写入，不自动覆盖
```

### 文件

新方案使用新文件路径：

```text
/faucet_cal_session_v1.bin
/faucet_cal_session_traces_v1.bin
/faucet_cal_samples_v1.bin
```

旧脉冲明细或旧样本文件不迁移、不删除、不覆盖。页面和新逻辑只使用新方案文件。已有计量方案配置不属于旧样本文件，必须继续按现有计量方案模型读取和保护。

### RAM 最近明细

RAM 只保留最近 1 条完整脉冲明细。当前原始格式为：

```text
elapsedUs: uint32_t
```

单条最大原始边沿 4096 个：

```text
4096 * 4B = 16384B，约 16 KiB
```

加上头部、暂停窗口和状态字段，RAM 占用约 16-18 KiB。校准会话不得复制完整明细数组，只保存引用和摘要。

### 校准会话文件

`/faucet_cal_session_v1.bin` 保存小体积会话状态，不保存完整脉冲数组：

```text
sessionId
status
startedAt
updatedAt
attemptCount
validSampleCount
appliedSchemeId
generatedResultSummary
attempts[10]
```

每个 attempt 保存：

```text
attemptIndex
targetHintLabel: small/common/large/custom
targetHintMl
完整 WaterRecord 身份
sessionTraceSlot
actualMl
status: pendingActual / valid / skipped / invalid
skipReason
invalidReason
qualityFlags
```

### 校准会话样本区

`/faucet_cal_session_traces_v1.bin` 使用固定 5 槽位，每槽保存一条有效样本完整明细：

```text
slot 0..4
trace header
elapsedUs[4096]
```

空间估算：

```text
5 * 4096 * 4B = 81920B，约 80 KiB
加头部、暂停窗口、校验后约 85-95 KiB
```

开始新校准会话时清空或覆盖旧会话样本区。放弃/无效样本默认不占用会话明细槽位。

### 长期样本库

长期样本库容量以 `2026-06-11-flash-storage-consolidation-design.md` 为准，使用固定 5 槽位，每槽保存一条长期样本：

```text
slot 0..4
sample metadata
trace header
elapsedUs[4096]
```

空间估算：

```text
10 * 4096 * 4B = 163840B，约 160 KiB
加头部、元数据、校验后约 170-190 KiB
```

长期样本库不自动覆盖。满时提示用户删除旧样本。

### Flash 总量

首版不压缩原始明细，按固定槽位估算：

```text
会话样本区：约 85-95 KiB
长期样本库：约 170-190 KiB
合计：约 255-285 KiB
```

首版优先选择固定槽位和 `uint32_t elapsedUs`，因为可靠性和可测试性高。若后续 Flash 空间紧张，可再设计 `uint16_t deltaUs` 压缩格式，读取时还原为 `elapsedUs` 给分析代码使用。

## 样本保存规则

校准会话内：

- 用户保存实测容量后，系统自动保存本次有效样本明细到校准会话样本区。
- 普通用户不需要额外点击“保存明细”。
- 保存失败时，该样本不能算作有效样本，页面必须明确提示。
- 出水结束进入 `AwaitingActual` 前，系统必须先把本次完整脉冲明细写入会话样本区的 pending 槽位，并在会话 attempt 中保存完整 `WaterRecord` 身份。用户稍后录入实测容量时，只补充实测容量、校验质量、写记录校准元数据，并把 pending 槽位提交为 valid。

长期样本库：

- 只有用户明确点击“存入长期样本库”才写入。
- 长期样本库满时拒绝写入，不自动覆盖。
- 长期样本用于专业复盘、历史对比、从历史优质样本生成方案。

普通出水记录：

- 非校准流程的出水明细默认只保留在 RAM 最近缓存。
- 用户可从记录详情手动保存到长期样本库。

## 计量方案应用

普通校准会话生成合格结果后，用户确认应用：

```text
确认应用 -> 创建新计量方案 -> 启用新方案 -> 旧方案保留
```

新方案保存：

- 5 个计量参数。
- 结构化生成来源：校准会话或长期样本库。
- 样本数量。
- 实测容量范围。
- 最大绝对误差。
- 最大相对误差。
- 参与样本摘要。
- 来源为校准会话。

如果用户未把样本存入长期样本库，旧会话样本区在下次校准时可能被覆盖。因此方案记录必须保存生成依据摘要；完整脉冲明细只有在样本仍处于当前会话样本区或已存入长期样本库时可查看。

专业计量方案页从长期样本库生成方案时，仍采用“保存为新方案，再手动启用”的流程。

## 断电恢复

重启后：

- `Preparing`、`WaitingLocalRun`、`AwaitingActual`、`ReadyToGenerate`、`Generated` 会话可提示继续或放弃。
- `Running` 会话恢复时，本次尝试标记为无效，不参与生成，并提示“上次出水中断，不参与生成”。
- `Applied`、`Discarded`、`Failed` 不恢复操作，只保留摘要。

如果会话文件损坏，设备回到 `Idle`，页面提示校准会话不可恢复。已写入的普通出水记录和长期样本库不应被删除。

## 页面结构

### 校准页

默认展示引导式校准会话：

- 开始校准。
- 安全提示。
- 当前状态。
- 有效样本数、尝试次数、容量跨度。
- 当前步骤。
- 实测容量输入。
- 放弃本次。
- 生成结果。
- 确认应用。
- 高级入口：样本库。

### 计量方案页

- 当前启用方案。
- 方案列表。
- 新建、编辑、启用、删除。
- 从长期样本库生成方案。
- 方案依据。
- 手工测算工具。

### 记录详情页

- 普通出水详情。
- 校准出水标记和关联会话。
- 脉冲明细入口。
- 保存到长期样本库的专业操作。

### 样本库

样本库不是顶级导航，放在校准页高级入口：

- 查看最多 10 条长期样本。
- 删除长期样本。
- 查看样本详情。
- 从长期样本生成方案。

## 测试关注点

- 校准会话状态转移。
- Web 不暴露出水控制。
- 本地按键在校准模式下的短按/长按语义。
- 放弃样本不删除普通出水记录，不计入有效样本。
- 暂停后恢复样本不参与生成。
- 最少 2 条、推荐 3 条、最多 5 条有效样本规则。
- 最多 10 次尝试规则。
- 容量跨度质量分级。
- RAM 只保留 1 条明细。
- 会话样本区 3 槽位覆盖。
- 长期样本库 5 槽位不自动覆盖。
- 断电恢复和 `Running` 中断无效化。
- 生成并应用后创建新方案、启用新方案、保留旧方案。
- 校准出水计入统计和滤芯累计。

## 实施计划约束

- LittleFS 实际可用空间必须在实现计划中核对，确认约 285 KiB 样本文件预算可接受。
- 固定槽位文件的头部、校验和写入顺序必须在实现计划中细化，确保断电时不会产生半有效样本。
- 设备只保留当前/最近一次校准会话摘要。新会话开始时覆盖上一会话摘要和会话样本区；已应用方案必须保存生成依据摘要，因此不依赖上一会话文件长期存在。
