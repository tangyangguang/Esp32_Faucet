# 校准工作台设计

## 背景

记录页目前同时承担历史记录、脉冲明细入口、计量诊断和容量校准入口，职责混在一起。容量校准保存实测值时还会触发分段样本扫描和候选参数生成，导致保存动作不透明，也让用户难以区分“保存样本数据”和“更新系统计量参数”两个不同风险级别的操作。

新的设计把记录页恢复为历史记录页，把校准相关能力集中到独立的校准工作台。校准工作台通过顶部导航进入，不在记录页保留轻量入口。

## 目标

- 顶部导航新增“校准”，位于“记录”之后。
- 记录页只展示历史出水记录，以及 RAM 明细和已保存明细的查看入口。
- 校准页展示计量诊断、临时缓存、已保存明细三组状态卡片。
- 校准页展示最后一条可校准记录，并支持确认/校准容量。
- 确认容量只保存记录级真值，并同步匹配 RAM/Flash 明细的实测值；脉冲明细入库是独立操作，不执行分段拟合扫描，不修改系统控制参数。
- 分段候选参数由用户点击“生成候选参数”手动触发。
- 候选参数生成后只作为候选展示，用户点击“应用候选参数”后才写入当前系统参数。
- 应用候选参数前保留上一套已应用参数，提供一次性恢复能力。
- 页面展示样本质量、候选参数、误差、失败原因和当前应用状态，避免黑盒。
- 不提供任何远程出水控制能力。

## 非目标

- 不做多版本参数历史管理，只保留上一套已应用参数用于回退。
- 不引入后台任务队列或复杂异步扫描；首版生成候选参数走同步 POST -> 303 -> GET。
- 不新增远程启动、停止、暂停、恢复出水能力。
- 不改变历史出水记录结构，不静默清空用户记录、样本或配置。

## 导航与页面边界

顶部导航顺序调整为：首页、记录、校准、统计、预设、滤芯。

记录页保留：

- 历史出水记录分页。
- 每条记录的校准状态、实测容量和实测 P/L 展示。
- 每条记录的 RAM 明细、已保存明细查看入口。
- 保存/删除已保存明细的操作入口。

记录页移除：

- 计量诊断卡片。
- 临时缓存卡片。
- 已保存明细卡片。
- 进入校准页的轻量提示或快捷入口。

校准页负责：

- 当前计量诊断。
- RAM 临时缓存状态。
- Flash 已保存明细状态。
- 最新可校准记录。
- 确认/校准容量表单。
- 样本列表。
- 候选参数生成、展示、应用和恢复。

## 校准页信息结构

页面顶部显示三张诊断卡片：

- 计量诊断：当前控制 P/L、当前稳态 P/L、启动等效、可生成样本、已测容量、还需样本、候选/已应用状态。
- 临时缓存：RAM 明细条数、数据点、占用、容量上限。
- 已保存明细：Flash 样本条数、文件占用、单条点数上限。

最新记录区显示最后一条可校准记录：

- 以紧凑单行表格展示时间、目标、估算出水、脉冲、明细来源、样本状态和操作。
- 实际出水量输入框默认使用已确认容量或当前估算值。
- “确认容量”按钮；估算准确时直接确认，不准确时改为量杯读数。
- “保存到设备”和“删除已保存明细”作为独立按钮，不和容量确认绑定。

样本区展示有脉冲明细的数据：

- RAM 临时明细和已保存设备明细都展示。
- 状态标签包括 RAM 临时、已保存到设备、待确认容量、容量已确认、稳态失败、可入库、可参与生成。
- 不满足生成条件的样本也显示，避免用户不知道为什么不能生成候选参数。

候选参数区展示：

- 当前应用参数。
- 最近生成候选参数。
- 稳态 P/L、启动段水量、启动段脉冲、启动持续时间、全程平均 P/L、建议补偿。
- 样本数、容量覆盖范围、最大拟合误差、小容量误差、大容量误差。
- “生成候选参数”、“应用候选参数”、“恢复上一套参数”按钮。

## 操作语义

确认容量：

1. 校验设备待机、记录可校准、实测容量合法。
2. 保存记录级校准元数据。
3. 同步匹配 RAM 明细和已保存 Flash 明细的 `actualMl`。
4. 不执行 `computeSegmentedCalibration`。
5. 不写入系统分段计量参数。
6. 返回校准页并显示保存结果。

生成候选参数：

1. 只扫描已保存到设备的样本库，不扫描 RAM 临时明细。
2. 对每条样本识别稳态段并计算是否满足“已保存到设备 + 容量已确认 + 稳态识别成功”。
3. 可参与生成样本不足时只展示失败原因和还缺什么，不生成候选。
4. 可参与生成样本足够时生成候选参数和误差摘要。
5. 候选参数保存为“待应用候选”，不修改当前控制参数。

应用候选参数：

1. 校验存在有效候选参数。
2. 保存当前已应用参数为上一套参数。
3. 把候选参数写入系统配置。
4. 标记分段参数已校准。

恢复上一套参数：

1. 校验存在上一套参数。
2. 把上一套参数写回系统配置。
3. 清除或保留候选参数都可以；首版保留候选参数用于对照，但页面必须标注当前已恢复旧参数。

## 样本质量规则

候选生成至少需要两条可参与生成样本，且实测容量差异必须明显。为了让估算在小容量和大容量都越来越准，页面还应展示推荐质量：

- 可参与生成样本数：至少 2 条，推荐 5 条以上。
- 容量覆盖：至少覆盖小容量和大容量；页面显示最小实测容量和最大实测容量。
- 误差：展示最大拟合误差、小容量误差、大容量误差。
- 失败原因：未保存到设备、待确认容量、脉冲数据不足、稳态识别失败、容量差异太小。

32 条已保存明细是当前样本库上限。首版目标是在 32 条以内通过高质量、多容量分布样本生成足够稳定的计量参数，而不是追求无限样本历史。

## 持久化

已有数据继续保留：

- 出水记录。
- 记录级校准元数据。
- 已保存脉冲明细样本。
- 当前系统配置中的分段参数。

需要新增的持久化状态：

- 最近生成候选参数。
- 上一套已应用分段参数。
- 候选参数生成时间和样本摘要。

这些状态应放在系统配置或现有配置存储能力里，并提供版本迁移，不能因升级清空用户配置。若系统配置空间或结构不适合承载，应在实现前单独提出最小持久化结构变更方案。

## 反馈与进度

首版候选生成使用同步请求。点击“生成候选参数”后按钮通过现有 `once(form)` 变为禁用状态，页面返回后显示结果摘要。若上板实测生成时间超过 2 秒，再升级为分步扫描或状态轮询。

候选生成失败不改变当前参数。应用候选失败不清除候选参数。恢复失败不修改当前参数。

## 验证

- 更新路由测试，确认导航包含“校准”且记录页不再保留诊断三卡片。
- 更新 Web 源码测试，确认校准页包含三张状态卡片、最新记录、样本库、候选参数区和独立按钮。
- 增加配置迁移或配置往返测试，保护新增候选参数和上一套参数。
- 增加候选生成/应用/恢复的业务核心测试。
- 运行 `pio test -e native`。
- 运行 `pio run -e esp32dev`。
- 上板测试主固件时优先使用 `pio run -e esp32dev -t webota`。
