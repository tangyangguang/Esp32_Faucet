# Esp32Base 请求：完善内置 Web 导航与业务导航融合能力

请在 Esp32Base 项目中完善内置 Web 导航模型。当前 Esp32_Faucet 项目暴露出一个基础库层面的产品问题：业务页面才是设备的最高频入口，但 Esp32Base 内置页面目前会以固定导航和固定首页形态呈现，导致业务导航、基础库导航、业务首页入口无法自然融合。

## 背景

Esp32_Faucet 是一个基于 ESP32 的智能定量出水龙头固件。用户日常最高频访问的是业务页面，例如状态、配置、统计、记录、滤芯、校准。Esp32Base 提供的是设备基础能力，例如 WiFi、OTA、日志、重启、系统状态等，这些页面重要但低频。

当前访问 `http://设备地址/esp32base` 时，页面顶部会显示 Esp32Base 内置导航，同时又列出 Application 业务链接。结果是：

- 业务入口不是最高优先级。
- 内置导航和业务导航混在一起。
- 页面里同时出现顶部导航和 Application 纵向按钮，信息重复。
- 内置导航存在英文标签，与中文业务页面风格不一致。
- 应用项目如果想美化，只能用 CSS 隐藏或额外插入导航，这会变成应用层打补丁。

## 目标

Esp32Base 的 Web 能力需要支持“业务应用是主界面，基础能力是系统工具”的导航关系，让应用项目可以声明自己的业务导航、默认首页、应用名称和基础功能入口位置，而不需要绕过或隐藏基础库输出。

## 现状问题

1. Esp32Base 首页固定以基础库为中心，不适合业务设备的日常使用。
2. 基础库内置导航与应用导航缺少统一的组合机制。
3. 应用页面和基础库页面的导航风格无法统一。
4. 基础库页面标签无法由应用项目统一本地化，例如 Home、Logs、Reboot。
5. Application 链接以列表按钮形式重复出现，不适合作为设备首页的信息架构。
6. 应用项目无法明确指定设备首页应该跳转到业务首页，还是展示融合后的首页。

## 期望能力

- 支持应用项目声明设备名称、业务首页、业务导航项和基础功能导航项。
- 支持将 `/` 或基础库首页配置为业务首页优先，或配置为融合首页。
- 支持基础库页面复用同一套导航框架，使业务页面和基础页面看起来属于同一个设备。
- 支持应用项目决定基础功能入口的展示层级，例如顶部、底部、折叠区、系统工具区等。
- 支持应用项目覆盖内置页面导航标签，至少能完成中文本地化。
- 避免 Application 区域重复列出已经出现在主导航里的业务页面。
- 保留 Esp32Base 默认开箱即用行为；没有应用配置时仍可显示基础库默认首页和默认导航。

## 影响范围

- Esp32Base Web 首页。
- Esp32Base Web 导航生成逻辑。
- 应用路由注册和导航注册方式。
- 内置 WiFi、OTA、Logs、Reboot 等页面的导航一致性。
- 应用项目对默认首页和导航标签的配置方式。

## 验证方式

- 在 Esp32Base 示例项目中验证默认行为不丢失。
- 在 Esp32_Faucet 中验证：
  - 打开设备地址时优先看到业务主界面或融合后的设备首页。
  - 顶部导航只出现一套清晰导航。
  - 业务页面和基础页面导航结构一致。
  - WiFi、OTA、系统日志、重启等基础页面可以访问，但不会抢占业务主流程。
  - 中文业务项目中不再出现 Home、Logs、Reboot 等不可配置英文标签。

## 为什么不应在 Esp32_Faucet 中临时绕开

这个问题不是单个页面样式问题，而是基础库 Web 信息架构和导航组合能力不足。如果 Esp32_Faucet 继续通过隐藏内置导航、重复生成业务导航、把基础功能入口塞到页面局部等方式解决，会导致：

- 每个应用项目都要重复处理同一类导航冲突。
- 基础库页面和业务页面难以保持一致。
- 后续新增基础库页面或业务页面时容易再次出现重复入口。
- 应用项目会承担本应由基础库统一处理的 Web 框架职责。

请在 Esp32Base 中从导航模型和首页模型层面完善这个能力，而不是要求应用项目继续做局部 CSS 或页面结构补丁。
