# 分段计量诊断与手动校准

## 背景

当前流量计在大容量接水时表现稳定，例如 7.5L 记录可得到约 221P/L 的全程平均值；但同一系数用于 1.0L、1.5L 等小容量时会明显多出水。现场观察显示启动阶段存在爬坡：开阀后先有短暂停顿，随后小流量出水，几秒后才进入稳定流量。关阀阶段水和传感器都能快速停止，第一版不做尾段补偿。

因此单一 `pulsePerMl` 只能描述全程平均，不足以解释小容量误差。项目采用“分段计量”作为长期诊断和校准模型。

## 模型

总出水量 = 启动阶段出水量 + 稳态阶段出水量。

- 启动阶段：使用固定时长、固定脉冲数和反推水量描述，不直接套用稳态 P/L。
- 稳态阶段：使用稳定后的 `stablePulsePerLiter` 计算。
- 全程平均：保留 `overallPulsePerLiter`，用于和历史 7.5L 实验数据比对。

当前只保存和展示分段候选参数，不自动改变关阀控制。确认样本质量稳定后，再单独启用“应用到控制参数”。

## 脉冲明细采样

每次出水在 RAM 中按 1 秒记录全程脉冲明细：

- 本秒新增脉冲数。
- 本秒状态：`running`、`paused`、`completed`、`stopped`、`error`。

不保存秒序号、累计脉冲和估算水量；详情页实时计算这些派生值，以节省 RAM 并避免把当前估算逻辑固化进历史样本。

RAM 只作为临时采集缓存。系统配置 `pulseTraceMemoryKb` 控制 RAM 上限，默认 50KB，可配置范围 10-50KB。超限后删除最旧明细，尽量保留更多最近接水数据。

需要长期参与分段校准的明细保存到 Flash 的已保存明细文件。该文件保存原始秒级样本和用户输入的实测容量 `actualMl`，作为持久样本库；不保存秒序号、累计脉冲和估算水量。

## 页面展示

校准页顶部把校准状态拆成三组卡片，避免计量信息和存储信息挤在同一块里：

- 计量状态：控制 P/L、稳态 P/L、启动补偿、启动等效、全程平均和建议补偿。
- 样本覆盖：可生成样本数、容量范围、拟合误差、还缺什么、已保存明细和已测容量。
- 明细存储：RAM 临时缓存和 Flash 已保存明细的条数、点数、占用和单条上限。

参数含义：

- 控制 P/L：当前实际参与关阀控制的单系数，内部按 `pulsePerMl = 控制P/L / 1000` 使用。
- 启动补偿：当前实时估算中追加的固定补偿量。
- 稳态 P/L：由样本库拟合得到的稳定流量阶段候选值。
- 启动等效：拟合得到的启动阶段等效水量、持续时间和启动段脉冲，主要用于解释启动爬坡。
- 全程平均：最大容量样本的总脉冲 ÷ 实测容量，只用于长期诊断和对照历史大容量实验。
- 建议补偿：把分段模型折算回当前单系数控制时的候选启动补偿。
- 拟合误差：当前样本对候选模型的最大容量误差。

记录页只承担历史记录和脉冲明细入口。“脉冲”列显示“明细”标识：有 RAM 脉冲明细时显示“明细”，有 Flash 明细时显示“已存明细”，点击进入详情页。记录页进入详情时顶部导航保持“记录”；校准页样本区进入详情时使用 `/faucet/calibration/detail` 隐藏路径，顶部导航保持“校准”。

详情页支持 1s、2s、3s、5s 聚合查看：

- 每桶脉冲折线图。
- 累计脉冲数据。
- 原始秒级明细默认展示 `0秒` 到 `30秒`，包含第 30 秒；超过 30 秒的明细通过“显示所有明细”打开完整文本。
- 自动识别的稳态开始秒。
- 本条明细占用、样本数、总脉冲和持续时间。
- 样本状态：容量是否已确认、明细来源、稳态是否识别成功、是否可参与候选参数生成。

## 稳态识别

第一版算法只分析 `running` 秒，暂停秒展示但不参与判断。

算法步骤：

1. 取后半段 running 样本估计稳定脉冲/秒。
2. 从前向后寻找连续窗口，要求窗口首秒达到稳定脉冲水平。
3. 窗口平均值接近后半段稳定值，且窗口内波动受限。
4. 找到后输出：
   - `stableStartSec`
   - `startupPulseCount`
   - `stablePulseCount`
   - `stablePulsePerSec`
   - `confidence`

如果明细太短、后半段无有效脉冲或波动过大，显示“无法识别”。

## 确认容量与手动生成

用户在校准页的最新记录中执行“确认/校准”。最新记录表将系统估算值和已确认容量分列展示；点击“确认/校准”后在该表格下方展开输入行。如果估算值准确，直接确认；如果不准确，改为量杯读数后确认。确认容量是样本真值来源，未确认时不能把系统估算值当真值参与拟合。

确认容量保存后只做两件事：

1. 写入记录级校准元数据，用于记录页展示和核对实测 P/L。
2. 同步匹配 RAM 明细和已保存设备明细的 `actualMl`。

确认容量不会触发分段拟合、候选生成、参数应用，也不会自动把 RAM 明细保存到设备。脉冲明细入库是独立操作：校准工作台只用 `RAM 中`、`已保存到设备` 等来源标签跳转到脉冲明细页，保存或删除明细只在明细页执行。

样本区展示有脉冲明细的数据，包括 RAM 临时明细和已保存设备明细。样本区上方可选择“前几秒脉冲总数”，范围 1-60 秒，默认 10 秒；该列只用于观察启动阶段脉冲分布，不影响样本是否参与生成。

参与生成候选参数的规则固定为：

- 已保存到设备。
- 容量已确认。
- 稳态识别成功。

RAM 临时明细即使质量合格，也只显示为“可入库”，必须进入明细页保存到设备后才能参与生成。已保存但未确认容量的明细显示“待确认容量”，不参与生成；不可靠明细在明细页删除。

参数生成通过独立按钮手动触发，只扫描设备样本。至少需要两条可参与生成样本，且容量差异明显。计算方式：

1. 对每条可参与生成样本识别 `stablePulseCount`、`startupPulseCount` 和 `stableStartSec`。
2. 用所有可参与生成样本拟合 `actualMl = startupVolumeMl + stablePulseCount / stablePulsePerMl`。
3. 由拟合斜率计算 `stablePulsePerLiter`。
4. 由拟合截距计算 `startupVolumeMl`。
5. 启动段时长和启动段脉冲取样本均值。
6. 用最大容量样本计算 `overallPulsePerLiter`，作为长期全程平均参考。
7. 计算最大拟合误差，用于判断候选参数是否可信。

应用候选参数前保留上一套参数；恢复上一套只回滚参数，不删除候选结果，方便继续对比和重新应用。

当前实时出水估算仍使用单系数加启动补偿：

```text
估算出水量 = round(脉冲数 / 控制P/ml) + 启动补偿
控制P/ml = 控制P/L / 1000
```

候选生成使用分段拟合模型：

```text
实测容量 ≈ 启动等效水量 + 稳态脉冲数 × 1000 / 稳态P/L
```

应用候选后，系统会把当前控制 P/L 设置为候选稳态 P/L，并把启动等效折算成启动补偿。`overallPulsePerLiter` 只做诊断，不直接参与关阀控制。

保存后的长期配置：

- `overallPulsePerLiter`
- `startupDurationSec`
- `startupPulseCount`
- `startupVolumeMl`
- `stablePulsePerLiter`
- `segmentedMeteringCalibrated`

## 上板实验流程

1. 保持当前单一系数控制，不启用分段控制。
2. 依次测试 1.0L、1.5L、2.0L、3.0L、7.5L，每个容量至少 5 次。
3. 每次接完后在校准页确认最新记录容量；估算准确时直接确认，不准确时输入量杯读数。
4. 查看 1s、3s、5s 聚合图，确认启动爬坡和稳态开始秒是否一致。
5. 将质量合格的 RAM 明细保存到设备，累积跨容量样本。
6. 手动生成候选参数后对比：
   - 全程平均 P/L 是否接近 7.5L 历史约 221P/L。
   - 稳态 P/L 是否在多次实验中稳定。
   - 启动段水量是否能解释小容量多出水。
7. 当多容量、多次实验误差稳定后，再评估是否应用候选参数参与关阀控制。

## 限制

- RAM 脉冲明细重启后消失；需要参与候选生成的样本必须成功保存到 Flash 明细库。
- 第一版稳态识别是启发式算法，低脉冲频率下建议优先查看 3s 或 5s 聚合图。
- 容量确认依赖用户判断或量杯读数；确认错误会直接影响候选参数质量。
- 当前候选参数不自动修改关阀控制；是否应用到控制参数需要后续单独确认。
- 第一版不处理关水尾段，因为现场验证水阀和传感器停止干脆。
