# 测试计划草案

## 当前已确认原则

- 先做 native 可测逻辑，再做上板集成验证。
- 测试计划需要覆盖安全关阀、流量精度、断网本地运行、Web 操作不影响控水等核心风险。
- 测试范围随实现范围收敛，不为不做的功能编写测试。

## Native 测试草案

- 三键输入：短按、长按、消抖、`STOP + OK` 组合、运行中 `NEXT` 无效。
- 状态机：待机、确认、运行、暂停、错误、恢复待机。
- 安全兜底：最大时间、最大出水量、超预设百分比、无流量、异常流量。
- 流量计算：脉冲计数、过滤、单一校准系数。
- 长期运行：`millis()` / `micros()` 回绕后的超时、流量、电磁阀、显示和蜂鸣器行为。
- 本地校准：目标容量选择、采样计算、两次采样偏差检查、确认保存、取消不保存。
- 电磁阀：全压吸合、PWM 保持、关阀幂等。
- 配置：默认值、钳位、版本不匹配恢复默认。
- 日志：追加、分页、容量滚动。
- 统计：今日、本周、本月、总累计更新。
- 滤芯：最多 6 个滤芯，出水完成后累计流量，重置后重新计算天数和流量。
- Web 边界：路由表和页面中不存在启动出水、暂停出水、继续出水、停止出水入口。
- Web API：配置、预设、日志、统计、滤芯、校准接口返回小 JSON，危险操作只接受 POST。

## 上板测试草案

- GPIO：三个按键、电磁阀、流量计、蜂鸣器、I2C OLED。
- 网络：WiFi 配网、mDNS hostname、Web Basic Auth、OTA 入口。
- 本地校准：用量杯完成至少两次采样，偏差合格后保存新系数。
- 断网：WiFi 断开时本地启动、暂停、停止正常。
- 异常：拔掉流量计、关闭水源、模拟超时。
- 休眠：OLED 熄屏和按键唤醒。

## 验收标准

- `STOP` 软件停止响应不超过 50ms。
- 自动关阀动作不超过 100ms。
- 校准后定量误差不超过 ±3%。
- 本地流量校准必须能脱离 Web 完成。
- Web 端不得存在任何出水控制入口或 API。
- 断网不影响本地出水。
- Web 日志分页查询不影响控水 tick。
- Web API 路径不得出现 `/water/`、`/start`、`/stop` 这类远程出水控制语义。
- 重启后默认不继续未完成出水任务。
- 出水过程中所有异常优先关阀。
- 恢复出厂必须经过 OLED 二次确认。
- 本地菜单不得修改预设值。
- 日志容量以 LittleFS 空间和性能验证后的合理值为准，目标尽量接近 20000 条。
- 滤芯查看支持最多 6 个滤芯，显示已用天数和已用流量。

## 已确认测试策略

- 长期运行测试做 72 小时连续运行。
- Native 测试使用 PlatformIO native 环境，业务核心保持纯 C++ 可测，硬件访问通过桩替代。
