# 流量计计量方案设计

本文定义“流量计计量方案”的新模型，用于替代旧的固定编号计量配置。本文只描述方案设计，不包含代码实施步骤。

## 目标

流量计计量方案用于保存水流量计把脉冲换算成水量时使用的一整套参数。它和具体流量计、水路、水压、滤芯状态、安装环境有关。

系统需要支持多套方案，目的包括：

- 实验时保存多套参数，便于切换对比。
- 长时间启用某套方案后发现效果不好，可以快速切回以前验证过的方案。
- 不同水压、水路或流量计条件下，可以使用不同方案。
- 生成候选计量方案后，先查看结果和样本依据，再决定是否保存和启用。

## 命名

页面和文档统一使用以下名称：

- 流量计计量方案：一套可保存、可启用的计量参数。
- 当前计量方案：设备正在用于出水估算的方案。
- 候选计量方案：根据样本生成、尚未保存为正式方案的结果。
- 新建计量方案：手工输入名称和 3 个核心参数创建的方案。
- 修改计量方案：修改已有方案的名称和 3 个核心参数。
- 可用方案：可以被选择启用的方案。
- 停用方案：保留历史追溯，但不出现在日常启用选择中的方案。

不再使用固定位置编号作为用户概念。

## 核心计量参数

每套方案真正参与计量的字段只有 3 个：

- 启动脉冲数 `Ns`
- 启动水量 `Vs`
- 稳态 P/L `Ps`

计量公式保持不变：

```text
P = 0:
  V = 0

0 < P <= Ns:
  V = round(P * Vs / Ns)

P > Ns:
  V = Vs + round((P - Ns) * 1000 / Ps)
```

`Ns = 0` 且 `Vs = 0` 时，启动段等价于没有，全部有效脉冲按稳态 P/L 计算。

## 方案数量与状态

业务上不设置固定的方案数量上限。页面不能把某个固定数量作为用户规则，也不能显示固定空位。

方案列表按动态数据展示。默认显示当前方案和可用方案；停用方案默认折叠或通过筛选查看。

底层实现可以有工程容量边界，用于保护 Flash、RAM 和页面响应时间。但这个边界不是产品概念。达到工程容量时，只允许用户删除未使用过的方案，或提示需要清理未使用方案。

每套方案有状态：

- 可用：可以被启用，也可以修改。
- 停用：不能直接作为启用选择，仍可查看、修改和恢复为可用。

当前计量方案必须始终是可用方案。

## 方案数据

每套方案保存以下结构化数据：

- `id`：稳定 ID，创建后不复用。
- `valid`：是否有效。
- `enabled`：是否可用。
- `name`：用户可编辑名称。
- `meterLabel`：流量计标识。
- `installationLabel`：水路或安装位置。
- `conditionLabel`：水压、滤芯状态或实验环境标签。
- `userNote`：用户备注。
- `startupPulseCount`：启动脉冲数。
- `startupVolumeMl`：启动水量，单位 ml。
- `stablePulsePerLiter`：稳态 P/L。
- `sourceType`：`default`、`generated`、`manual`、`migrated`。
- `revision`：方案修订号，创建为 1，修改核心参数或环境信息时递增。
- `createdAt`：创建时间。
- `updatedAt`：最近修改时间。
- `lastActivatedAt`：最近启用时间。
- `useCount`：累计成功出水记录使用次数。
- `lastUsedAt`：最近一次用于出水记录的时间。
- `sampleCount`：生成时使用的有效样本数量。
- `sampleTraceIds`：生成时参与样本的设备明细 ID 摘要。
- `minActualMl`：生成样本中的最小实测水量。
- `maxActualMl`：生成样本中的最大实测水量。
- `maxErrorMl`：生成拟合后的最大误差。
- `maxErrorPercent`：生成拟合后的最大相对误差。
- `startupDurationMinSec`：启动阶段最小时长。
- `startupDurationMaxSec`：启动阶段最大时长。
- `startupDurationMedianSec`：启动阶段中位时长。
- `startupDurationAvgSec`：启动阶段平均时长。
- `creationSummary`：创建说明。
- `lastModifiedSummary`：最近修改说明。

`sampleCount` 到 `startupDurationAvgSec` 是创建时的样本依据快照。方案后续被修改时，这些创建依据不变，只更新最近修改信息和 `revision`。

手工新建方案没有样本依据，`sourceType` 为 `manual`，样本统计字段为 0，创建说明显示“手工创建”。

## 候选计量方案

候选计量方案来自已保存样本的生成结果。生成候选不会保存正式方案，也不会影响当前计量。

候选方案显示：

- 3 个核心计量参数。
- 样本数量。
- 实测水量范围。
- 最大误差。
- 最大相对误差。
- 启动阶段时长：中位数、平均数、最小值、最大值。
- 生成时间。

候选方案只提供两个操作：

- 保存为新方案。
- 丢弃候选。

候选方案不能直接启用，不能覆盖已有方案，也不能覆盖当前启用方案。

保存候选后，系统创建一套新的流量计计量方案。保存动作不启用新方案。用户需要显式点击“启用方案”后，设备才切换计量参数。

## 操作规则

### 生成候选计量方案

系统只使用已保存到设备、容量已确认、未截断且稳态识别成功的样本生成候选。

RAM 临时明细只用于查看，不直接参与生成。需要参与生成时，先保存到设备样本库。

候选生成必须有明确质量门槛：

- 有效样本数量不少于 3 条。
- 样本容量覆盖小容量和大容量，最大实测水量和最小实测水量差值不少于 500ml。
- 参与样本必须保存设备明细 ID，便于追溯。
- 生成结果保存最大绝对误差和最大相对误差。
- 最大绝对误差不超过 100ml，最大相对误差不超过 5%。超过阈值时，只显示诊断结果，不生成可保存候选。
- 若同一容量附近有多次样本，应记录重复性差异。相邻实测水量差值不超过 200ml 的样本视为同一容量附近。
- 稳态识别失败、暂停恢复、明细截断或未确认实际容量的样本不能参与生成。

质量门槛不满足时，页面只能显示诊断原因，不能生成可保存的候选方案。

### 保存为新方案

保存候选时只能创建新方案，不允许选择已有方案覆盖。

如果底层工程容量已满，保存失败并提示先删除未使用过的方案。

保存成功后，候选可以清空，避免重复保存同一候选。

### 新建计量方案

用户可以手工新建方案，填写：

- 方案名称。
- 启动脉冲数。
- 启动水量。
- 稳态 P/L。

手工新建方案不需要样本依据，不自动启用。

### 修改计量方案

修改页允许编辑：

- 方案名称。
- 流量计标识、水路或安装位置、环境标签和备注。
- 启动脉冲数。
- 启动水量。
- 稳态 P/L。

修改不改变创建依据。系统只更新 `updatedAt` 和 `lastModifiedSummary`。

如果修改的是当前启用方案，保存后会立即影响计量，页面必须明确提示这一点。

修订号规则：

- 新建方案的 `revision` 为 1。
- 修改 3 个核心计量参数时，`revision` 必须递增。
- 修改流量计标识、水路或安装位置、环境标签、备注时，`revision` 必须递增，因为这些字段会改变方案适用条件。
- 只修改方案名称时，`revision` 不递增。
- 后续历史记录展示以出水记录中的计量快照为准，不能用方案当前 revision 的参数反推历史。

已经被出水记录使用过的方案仍允许修改，但每次影响计量或适用条件的修改都必须形成新的 `revision`。创建依据始终代表最初创建时的样本快照，最近修改信息代表当前方案最近一次修改。

### 启用方案

启用是单独操作。只有启用后，方案才成为当前计量方案。

只有可用方案可以启用。停用方案需要先恢复为可用，再启用。

启用方案时更新：

- `activeSchemeId`
- 方案的 `lastActivatedAt`
- 运行时 `FlowMeter` 使用的计量参数

启用不修改方案的创建依据或最近修改说明。

### 停用与删除方案

当前计量方案不能停用，也不能删除。若用户要停用或删除当前方案，必须先启用另一套可用方案。

已经被出水记录使用过的方案不能删除，只能停用。停用后不出现在日常启用选择中，但仍保留在停用方案列表和历史追溯中。

从未被使用过的非当前方案可以真正删除。删除后释放存储空间，方案 ID 仍不复用。

系统必须始终保留至少一套可用方案。

## 出水记录追溯

每条成功生成的出水记录必须保存当时的计量快照：

- `meteringSchemeId`
- `meteringSchemeRevision`
- `startupPulseCount`
- `startupVolumeMl`
- `stablePulsePerLiter`

这些字段用于保证历史记录不依赖方案是否仍处于可用状态。方案中的 `useCount` 是累计使用次数，用于页面显示“使用 N 次”并判断是否允许物理删除。

使用次数一致性规则：

- 只有出水记录成功写入后，才增加对应方案的 `useCount`。
- 如果出水记录写入失败，不增加 `useCount`，避免方案状态和历史记录不一致。
- `useCount` 是累计值，不因历史记录环形覆盖而减少。
- `lastUsedAt` 在成功写入出水记录后同步更新。
- 如果更新 `useCount` 或 `lastUsedAt` 失败，设备应记录告警；后续可以通过扫描出水记录重建使用次数。

## 页面结构

校准页按任务分区：

1. 当前计量方案
   - 显示当前启用方案名称。
   - 显示 3 个核心参数。
   - 显示创建来源、样本依据和最近修改。

2. 候选计量方案
   - 显示生成结果和样本依据。
   - 提供“保存为新方案”和“丢弃候选”。
   - 明确提示“保存不会自动启用”。

3. 流量计计量方案
   - 动态列表显示已有方案。
   - 当前启用方案有明确标记。
   - 每套方案显示名称、参数摘要、来源、样本摘要、使用次数和最近修改。
   - 可用方案操作包括“启用”“修改”“停用”或“删除”。
   - 停用方案默认折叠，操作包括“恢复为可用”“修改”和“查看”。
   - 从未使用过的非当前方案才显示“删除”。

4. 新建计量方案
   - 提供手工新建入口。
   - 新建后不自动启用。

5. 样本区
   - 展示已保存样本和 RAM 临时明细。
   - 显示容量确认、稳态识别、是否可参与生成。

## 存储策略

流量计计量方案应从 `SystemConfig` 中拆出，使用独立的 `MeteringSchemeStore` 管理。

`SystemConfig` 继续保存安全阈值、显示、蜂鸣器、滤芯、预设等系统配置。流量计计量方案独立保存：

- 计量方案存储版本。
- 当前启用方案 ID。
- 下一个方案 ID。
- 方案数量。
- 方案记录。
- 候选计量方案。

保存方案时只写入被修改的方案和必要索引，不重写整个系统配置。启用只写当前启用 ID 和被启用方案的启用时间；停用、恢复、修改和删除只写对应方案记录。这样可以减少写入量，降低 Flash 磨损。

方案数量不再是固定小数组，因此方案记录适合使用独立记录式持久化。当前启用 ID、存储版本和少量索引可以放在 NVS；方案记录可以放在 LittleFS 定长记录文件或等价的记录式存储中。脉冲明细样本仍使用已有设备样本库，不放入方案配置。

## 迁移规则

从旧固定编号计量配置迁移时：

- 当前启用槽迁移为一套方案，作为当前计量方案。
- 其他槽如果有效且不是默认参数，迁移为独立方案。
- 默认但未实际使用的空意义槽不迁移。
- 旧候选如果存在，迁移为候选计量方案。
- 旧创建说明和最近修改说明尽量保留到新方案对应字段。
- 迁移出的方案默认标记为可用，使用次数从 0 开始。
- 迁移完成后不再读写旧固定编号计量字段。

迁移必须保护用户已有配置，不能因升级静默清空可识别方案。

## 文案原则

- 不使用固定位置编号作为用户概念。
- 不使用“覆盖当前方案”作为候选保存动作。
- “保存为新方案”和“启用方案”必须分开。
- 所有会影响当前计量的操作必须显式提示。
- 已使用方案不显示删除入口，只显示停用入口。
- 每套方案必须显示使用次数。
- 生成样本依据作为创建信息永久保留。
- 修改方案只更新最近修改信息，不改变创建信息。
