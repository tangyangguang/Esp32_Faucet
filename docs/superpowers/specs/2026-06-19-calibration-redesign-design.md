# 校准页面与逻辑重设计

## 背景

当前校准页面把流量计校准、计量方案管理、长期样本库、脉冲明细、温度校准和水质校准放在同一套页面逻辑中。用户需要理解“保存样本”“生成方案”“保存为新方案”“应用方案”等概念，导致主流程不自然，页面也显得繁琐。

本设计重新定义校准中心的用户心智：普通用户只需要理解“当前参数”和“确认使用新结果”；技术样本库保留，但降级为高级观察和诊断入口。

## 设计目标

- 校准主流程简洁：进入校准、接水、输入实测、查看结果、确认使用。
- 设备任意时刻只有一组当前流量计计量参数。
- 历史参数作为旧参数快照，用于查看和复制，不作为“方案列表管理”。
- 样本库保留为技术观察库，主要用于查看脉冲图、稳态开始、启动段和样本可用性。
- 温度和水质校准改为进入式流程：校准中心只展示状态，详情页才开始校准。
- 水质校准采用“校准点”模型，不让用户先选择单点或两点；点数决定结果质量。
- Web 仍不得提供任何远程出水、停水、暂停或继续能力。
- 页面和接口不得阻塞控制 tick；样本库和脉冲明细必须分页或小响应。

## 非目标

- 不实现 Web 远程控水。
- 不让普通校准流程依赖长期样本库。
- 不提供普通用户视角的方案删除、样本库生成方案主流程。
- 不为旧页面、旧字段、旧 API 保留长期兼容包袱。
- 不把高级算法阈值继续作为普通配置项暴露给用户。

## 核心概念

### 当前流量计参数

设备实际用于出水估算的唯一参数组。普通页面围绕它展示当前状态、最近更新时间、来源摘要和是否已校准。

### 待确认流量计参数

由现场校准、手工输入、复制历史参数或样本库辅助计算得到。待确认参数不会影响出水，用户点击“使用这组参数”后才替换当前参数。

### 历史参数

以前生效过的参数快照。历史参数默认只读，普通操作只有查看和复制。复制历史参数会把参数带入手工输入/待确认流程，不直接改变当前参数。

### 本次校准样本

当前校准会话中接水并输入实测容量后形成的样本。样本可移除，移除后不参与本次结果，并自动重新计算待确认参数。

### 高级样本库

用于技术查看和诊断的样本集合。主要价值是查看历史接水样本的脉冲图、稳态识别、启动段分析、暂停/截断/过滤脉冲等事实。样本库可以提供“辅助重新计算参数”，但结果只显示或带入手工输入，不直接应用。

### 水质校准点

一次稳定水样采集形成一个水质校准点，包含参考 ppm、采样原始 ppm、采样电压、水温和稳定状态。用户不需要先理解“单点校准”或“两点校准”；系统按已保存校准点自动生成待确认水质参数。

### 当前水质参数

设备实际用于 TDS 显示和出水记录的水质校准参数，包括 `scale`、`offset`、校准点摘要、校准时间和温度补偿状态。它不影响出水计量、阀门控制或安全停水。

### 待确认水质参数

由本次水质校准点自动计算得到。待确认水质参数不会影响当前显示和记录，用户点击“使用这组参数”后才替换当前水质参数。

## 流量计校准流程

### 普通流程

1. 用户进入流量计校准。
2. 页面说明必须在设备旁用本地按键接水，Web 不提供启动或停水。
3. 用户开始校准会话。
4. 每次本地接水结束后，页面等待用户输入量杯实测容量。
5. 输入后生成一条本次校准样本。
6. 有效样本少于 2 条时，只提示还需要继续接水。
7. 有效样本达到 2 条后，自动生成待确认参数。
8. 第 3 到第 10 条有效样本继续更新待确认参数。
9. 用户可继续接水、移除样本、放弃会话，或使用当前结果。
10. 用户确认后，待确认参数替换当前参数，旧当前参数进入历史。

当前校准会话不提供“生成参数”按钮。参数生成是系统在样本变化后的自动结果：新增有效样本、移除样本或修改实测容量后，系统自动重新计算待确认参数。用户只决策是否使用当前结果。

### 样本数量规则

- 最少 2 条有效样本才生成待确认参数。
- 最多 10 条有效样本。
- 页面不在开始时强调最大值；达到上限时提示“本次校准样本已满，请使用当前结果或重新开始校准”。
- 无效、放弃或被移除的样本不计入有效样本上限。

### 样本移除

- 本次校准样本列表允许移除单条样本。
- 文案使用“移除”或“不参与本次结果”，避免使用“删除”。
- 移除只影响当前校准会话，不修改历史参数或高级样本库中的已保存事实。
- 移除后自动重新计算待确认参数。
- 如果移除后有效样本少于 2 条，则隐藏可使用结果并提示继续接水。

### 结果质量

硬阻断只用于明确不可用情况：

- 有效样本少于 2 条。
- 样本无有效脉冲。
- 脉冲明细截断，无法用于拟合。
- 暂停后恢复出水，包含多次启动过程。
- 参数计算结果不合法。
- 存储或读取失败。

质量提醒只作为提示，不阻断使用：

- 样本容量跨度偏小。
- 拟合误差偏大。
- 样本数量较少。
- 多条样本重复性差。

## 手工输入与历史参数

手工输入是所有非现场校准来源的统一确认入口：

- 用户直接输入参数。
- 用户从历史参数复制。
- 用户从高级样本库辅助计算结果带入。

这些入口都生成同一种待确认参数。用户确认后才替换当前参数。

历史参数页面不作为方案管理页。普通页面不提供删除历史参数；如后续确实需要清理 Flash，可放入高级维护入口。

## 高级样本库

### 定位

高级样本库是技术观察和证据库，不是普通校准主流程。

### 展示内容

样本列表展示：

- 接水时间。
- 实测容量。
- 有效脉冲数和过滤脉冲数。
- 出水用时。
- 是否可参与分析。
- 稳态开始时间。
- 启动阶段脉冲和估算水量。
- 是否暂停后恢复、是否截断、是否异常。

样本详情展示：

- 有效脉冲趋势。
- 原始边沿趋势。
- 被过滤边沿。
- 暂停时间窗。
- 稳态识别结果。
- 启动段分析。
- 使用的有效脉冲判定规则。

### 辅助重新计算

样本库可以提供基于选中样本重新计算参数的辅助功能。该功能必须降级处理：

- 不作为主入口。
- 结果只显示为计算结果。
- 可提供“带入手工输入”。
- 不直接提供“应用到当前参数”。

## 温度校准

温度校准改为进入式单步确认流程：

1. 校准中心只显示传感器启用状态、当前水温、当前偏移和校准状态。
2. 用户进入温度校准详情页。
3. 页面先显示当前传感器状态和当前偏移。
4. 用户点击开始校准。
5. 开始后页面显示实时原始温度和当前显示温度。
6. 用户输入温度计读数，单位为 `°C`。
7. 页面预览新偏移和保存后的显示温度。
8. 用户确认保存或取消。

页面不得让用户输入或理解 `0.01C` 这类内部单位。

第一版温度校准不引入后端持久会话。“开始校准”只是页面进入采样编辑状态，用于展示实时值和预览偏移。用户保存时，后端以提交瞬间的当前原始温度重新计算偏移并持久化；页面端预览只作辅助，不能作为最终写入依据。

## 水质校准

水质校准采用统一的校准点流程：

1. 校准中心只显示传感器启用状态、当前 TDS、采样电压、水温补偿状态和当前校准参数。
2. 用户进入水质校准详情页。
3. 用户点击开始校准。
4. 页面显示实时原始 ppm、当前校准后 ppm、采样电压、水温和稳定状态。
5. 用户把探头放入一个已知参考值的水样，输入参考 ppm。
6. 采样稳定后，用户保存为一个校准点。
7. 保存或移除校准点后，系统自动重新生成待确认水质参数。
8. 用户可以继续增加校准点，也可以使用当前结果。
9. 用户确认后，待确认水质参数替换当前水质校准参数。

### 本次水质校准会话

- 水质校准详情页只允许同时存在一个本次水质校准会话。
- 点击“开始校准”后创建会话；会话保存最多 5 个校准点和一个自动计算的待确认水质参数。
- 会话可以短暂跨页面刷新保留，避免误刷新丢失已采样点。
- 会话不作为长期历史保存；用户使用结果、放弃校准、传感器被禁用、设备重启或空闲超时后清空。
- 空闲超时建议沿用流量计校准的 30 分钟策略。超时只丢弃本次水质校准会话，不修改当前水质参数。
- 出水确认、运行、暂停期间不允许开始、保存校准点、移除校准点或使用结果。
- 采样中页面可轮询实时值，但接口必须小响应，不能阻塞控制 tick。

水质点数规则：

- 最少 1 个稳定校准点即可生成待确认结果。此时等价于单点校准，适合只有一瓶标准液或只关心当前常用水质区间的场景。
- 2 个校准点开始作为推荐结果。系统可同时修正比例误差和偏移误差，适合覆盖低值和高值两个区间。
- 3 到 5 个校准点用于提高覆盖范围和降低单次采样偶然误差。
- 最多 5 个校准点；页面不在开始前强调上限，达到上限时提示使用当前结果或重新开始。
- 每个校准点可以移除，移除后不参与本次结果。

页面不再同时展示“单点校准”和“两点校准”两个入口。单点、两点、多点只是结果说明，不是用户需要先选择的模式。

计算策略：

- 每个校准点使用采样窗口内稳定后的平均原始 ppm 作为 `rawPpm`，用户输入的参考值作为 `referencePpm`。
- 1 个点：沿用当前单点比例修正，生成 `scale = referencePpm / rawPpm`，`offset = 0`。
- 2 个点：沿用当前两点线性计算，按两个点生成 `scale` 和 `offset`。
- 3 到 5 个点：以 `rawPpm` 为 x、`referencePpm` 为 y，使用最小二乘直线 `y = scale * x + offset` 生成 `scale` 和 `offset`。
- 拟合计算使用所有未移除且稳定的校准点；点的输入顺序不影响结果。
- 2 个及以上校准点参与计算时，用参与点的最大值和最小值判断跨度：`referenceSpan = max(referencePpm) - min(referencePpm)`，`rawSpan = max(rawPpm) - min(rawPpm)`。
- 第一版沿用现有两点校准阈值：`referenceSpan >= 50 ppm` 且 `rawSpan >= 30 ppm` 才允许生成可使用结果。
- 写入配置前仍按现有配置边界校验 `scale`、`offset`、参考 ppm、采样电压和校准温度。第一版边界为 `0.05 <= scale <= 20.0`，`-2000 <= offset <= 2000`，`0 <= referencePpm <= 2000`，`0 <= voltageMv <= 2300`，`0C <= calibrationTemperature <= 60C`。

硬阻断只用于明确不可用情况：

- 没有稳定校准点。
- 任一参与计算的校准点缺少有效 `rawPpm` 或 `referencePpm`。
- 2 个及以上校准点的 `referenceSpan < 50 ppm`。
- 2 个及以上校准点的 `rawSpan < 30 ppm`。
- 多个校准点存在相同 `referencePpm` 但 `rawPpm` 差异超过 30 ppm，或相同 `rawPpm` 但 `referencePpm` 差异超过 50 ppm。
- 计算得到的 `scale` 非有限值、小于等于 0，或超出配置允许范围。
- 计算得到的 `offset` 超出配置允许范围。
- 传感器未启用、采样电压无效、TDS 原始值无效、存储失败或设备正处于出水 busy 状态。

质量提醒只提示，不阻止使用：

- 只有 1 个校准点。
- 参考值或原始 ppm 跨度刚好接近下限。
- 点位主要集中在单一水质区间。
- 多点拟合残差偏大但仍在允许范围内。
- 温度补偿回退到 25C。

## 页面结构

校准首页：

- 流量计校准：展示完整当前计量参数，包括启动脉冲、启动水量、启动时长、稳态 P/L、稳态流速、来源摘要和更新时间；提供进入校准、手工修改、历史参数入口。
- 温度校准：展示传感器启用状态、当前水温、当前偏移和校准状态；提供进入温度校准入口。
- 水质校准：展示传感器启用状态、当前 TDS、采样电压、水温补偿、当前 `scale` 和 `offset`；提供进入水质校准入口。
- 高级样本库入口：脉冲明细、样本分析、辅助重新计算。

流量计校准页：

- 当前参数摘要。
- 本次校准状态。
- 本次样本列表。
- 待确认参数结果。
- 使用结果、继续接水、放弃会话。

温度校准页：

- 当前传感器状态和当前偏移。
- 开始校准按钮。
- 校准中实时原始温度和当前显示温度。
- 参考温度输入。
- 新偏移和保存后温度预览。
- 保存或取消。

水质校准页：

- 当前水质状态和当前校准参数。
- 开始校准按钮。
- 校准中实时原始 ppm、校准后 ppm、采样电压、水温和稳定状态。
- 本次参考 ppm 输入。
- 已保存校准点列表。
- 每个校准点的参考 ppm、原始 ppm、采样电压、水温、稳定状态和是否参与结果。
- 待确认水质参数结果。
- 结果质量说明：1 点可用、2 点推荐、多点拟合、硬阻断原因或质量提醒。
- 使用结果、继续增加校准点、移除校准点、放弃本次校准。

高级样本库页：

- 样本列表，分页展示。
- 样本详情和脉冲图。
- 辅助重新计算。
- 带入手工输入。

## 旧概念处理

需要从普通页面移除或改名：

- “方案列表”改为“历史参数”。
- “保存为新方案”改为通过“使用这组参数”替换当前参数。
- “应用方案”改为“使用这组参数”。
- “长期样本库与参数生成”改为“高级样本库”。
- “重新生成参数”降级为高级样本库中的“辅助计算”。
- 当前校准会话中移除“生成参数”操作；达到最低样本条件后自动生成并自动更新。
- “删除方案”不出现在普通校准页面。
- “保存样本到长期库”不出现在普通校准主流程。

## 数据保留策略

- 当前参数必须长期保存。
- 历史参数保存以前生效过的参数快照和简要来源摘要。
- 本次校准会话最多保存 10 条有效样本及必要过程记录；少于 2 条有效样本时不生成待确认参数。
- 本次水质校准会话最多保存 5 个校准点；使用结果、放弃、超时或重启后清空，不作为长期历史库。
- 高级样本库保存有限数量的样本和脉冲明细，必须有工程容量边界。
- 普通页面不直接暴露底层存储槽位、样本文件、长期库容量等概念。

## 验证要求

- 修改业务核心、配置、Web handler、存储或安全边界后，运行 `pio test -e native`。
- 修改主固件集成、驱动接入、构建参数或分区相关内容后，运行 `pio run -e esp32dev`。
- Web 远程控水边界必须有 native 测试或明确路由/API 检查。
- 校准页面不得注册或暴露远程启动、暂停、继续、停止出水接口。
- 样本库、脉冲明细和历史参数页面必须分页或小响应，避免阻塞控制 tick。

## 实现决策

- 第一版高级样本库优先复用现有样本和脉冲明细存储，不扩大容量；如果实现时发现容量不足，再单独评估 Flash 和响应时间。
- 第一版历史参数优先复用现有计量方案存储结构，Web 文案和交互改为“当前参数/历史参数”；底层命名是否重构留给后续清理，不阻塞页面逻辑重做。
- 校准中心改为状态总览，不在首页铺开温度或水质表单。
- 温度校准预览优先在页面端即时计算：参考温度减去当前原始水温得到偏移；保存时仍由后端按当前原始读数校验并写入。
- 水质校准需要把现有 `WaterSensorManager` 的单点/两点会话模型升级为校准点会话模型：最多 5 个点，1 点可用，2 点推荐，3 到 5 点线性拟合。
- 第一版水质校准点和待确认水质参数保存在运行态内存。页面刷新不丢失，设备重启后丢弃，不落盘保存未完成会话。
